# 场景模板库

复制即用。每个场景给「一键模板」+「为什么这样写」。

---

## 💻 编程

### 修 Bug

```
语言/版本：___
期望：___
实际：___
代码：
[粘贴]
报错全文：
[粘贴]
请先分析根因，再给最小修改。不要重构无关部分。
```

### 代码审查

```
请审查这段代码，按严重程度排序：
【严重】会导致 bug 或安全问题
【中等】可维护性、性能
【轻微】风格、命名

每条：问题 → 为什么 → 怎么改。不要给赞美。
[粘贴代码]
```

### 学新技术

```
我要在一个真实项目里用到 [技术]。
我的背景：[已有技能]
请给一条最短学习路径：
1. 先讲 3 个必须理解的概念（用类比）
2. 给一个 30 分钟能跑通的 demo
3. 列出新手最容易踩的 3 个坑
```

## 📚 学习

### 彻底搞懂一个概念

```
我想彻底搞懂 [概念]。
请反问式教学：一次只问 1-2 个问题，根据我的回答往下；
不要一次讲完。
结束时给：3 条核心结论 + 2 个我容易误解的点 + 1 个下一步行动。
```

### 验证自己学会了

```
我已经学了 [主题]。请出 5 道题考我，
从易到难，不要给答案。
我答完后你再逐题点评。
```

## ✍️ 写作

### 改文章

```
请改写下面这段。
目标读者：[谁]
风格：[正式/口语/技术]
长度：[限制]
保留：[必须保留的信息]
去掉：[要删的]
[粘贴原文]
```

### 写邮件

```
帮我写一封邮件。
收件人：[谁，什么关系]
目的：[要达成什么]
语气：[正式/友好/强硬]
长度：不超过 [N] 字
背景：[相关情况]
```

## 🎯 决策

### 二选一

```
帮我决定：[选项A] vs [选项B]。
场景：[具体情况]
约束：[预算/时间/团队]
要求：先问我最多 2 个关键问题，再给明确推荐，
并说清这个推荐最可能错在哪。
```

### 事前验尸（预演失败）

```
假设这件事在 [时间点] 失败了。
请列出最可能的 3 个原因（按概率排序），
每个写：早期信号是什么 + 现在能做什么预防。
```

## 🔍 分析

### 深度分析一份材料

```
请分析下面内容。分三层：
1. 事实层：它说了什么（客观复述）
2. 逻辑层：论证是否成立，有无漏洞
3. 影响层：如果它是对的，意味着什么

不要评价文笔，只看逻辑。
[粘贴材料]
```

### 找问题（红队）

```
请扮演最挑剔的反对者，攻击下面的内容。
按严重程度排序：问题 → 为什么严重 → 怎么改。
不要给任何优点。
[粘贴内容]
```

## 🗣️ 沟通

### 化解冲突

```
我要跟 [谁] 沟通 [什么事]。
现状：[情况]
我的目标：[想要什么结果]
对方的立场：[他们怎么想]
请给 3 种策略，每种说清适用条件和风险。
```

### 说服/提案

```
我要说服 [谁] 接受 [方案]。
对方关心：[他们的利益点]
我的理由：[我的论据]
请按"对方在意什么"重新组织我的理由，
并预判他会提的 3 个反对意见 + 应对。
```

## 🧰 元技巧（对所有场景适用）

### 让它复述确认

```
请先用三点复述：①你理解的任务 ②主要约束 ③你的假设。
我确认后你再开始。
```

### 迭代纠偏

```
上一版方向对，但要调整：
保留：[___]
重写：[___]
请只改需要改的部分。
```

### 一行速写版

```
背景：___ ｜ 目标：___ ｜ 形式：___ ｜ 约束：___ ｜ 验收：___
```
