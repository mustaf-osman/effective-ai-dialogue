# 提示词工程基础 — 大白话版

> 不需要背术语。理解这几件事，你的提问质量立刻上一个台阶。

---

## 一、AI 不是"读心机"，它只看到你给的字

**核心事实：** 大模型每次回答，看到的**只有当前对话里的文字**。你没说的，它不知道。

```
❌ "帮我改一下"
```

改成什么样？为什么改？什么风格？它只能猜。

```
✅ "帮我把这段话改得更简洁，保留所有关键信息，
   目标读者是非技术人员，控制在 100 字内"
```

**这就是提示词工程的本质：把"你以为对方知道"的信息，明确写出来。**

---

## 二、五个要素（记住 COnTEX 就行）

| 要素 | 英文 | 问自己 |
|------|------|--------|
| **背**景 | Context | 我是谁？在做什么？已有什么材料？ |
| **目**标 | Objective | 我要的最终产物是什么？（结论/代码/文档） |
| **要**求 | Requirements | 深度、长度、语气、受众、禁止什么 |
| **形**式 | Format | 表格？清单？代码块？JSON？ |
| **验**收 | Acceptance | 怎么算做完了？怎么检查对不对？ |

**一行版模板：**

```
背景：___ ｜ 目标：___ ｜ 形式：___ ｜ 约束：___ ｜ 怎样算完成：___
```

## 三、三个常见错误

### 错误 1：一次问太多

```
❌ "帮我分析这个项目的架构问题、性能瓶颈、安全隐患、
    代码风格、测试覆盖、部署方案、未来规划"
```

AI 每个都只能蜻蜓点水。

```
✅ "先只分析架构问题，其他后面再说"
```

### 错误 2：不说"不要什么"

AI 默认会给你长篇大论。你不说"只要 3 条"，它就给你 20 条。

```
✅ "只给 3 条最重要的，每条不超过两句话"
```

### 错误 3：不给判断标准

```
❌ "写得好一点"
✅ "读起来像给同事写的邮件，不是营销文案，
    不用感叹号，不用夸张词"
```

---

## 四、两个关键技巧

### 技巧 1：让它先复述（防跑偏）

```
请先用三点复述：①你理解的任务 ②主要约束 ③你的假设。
我确认后你再开始。
```

**为什么有用？** 复杂任务里，AI 理解偏了，写了半小时才发现白干。先复述只要 10 秒。

### 技巧 2：给例子（Few-shot）

```
按这个风格改写：
输入："这个功能很慢"
输出："响应时间达到 3 秒，超过了 500ms 的目标"

现在改写："这个功能有时候会崩"
```

**给它一两个例子，比写十句要求都管用。**

---

## 五、一句话总结

> **提示词工程 = 把"你以为对方知道"的，都明确说出来 + 给判断标准 + 给例子。**

不需要魔法咒语，需要的是**说清楚**。
