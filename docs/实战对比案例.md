# 实战对比案例 — 坏提问 vs 好提问

同样的需求，不同的问法，结果天差地别。

---

## 案例 1：改代码

### ❌ 坏的

```
这段代码有问题，帮我看看
```

**AI 的结果：** 泛泛地说"这里可以用更好的命名""建议加注释"，实际 bug 没找到。

### ✅ 好的

```
语言：Python 3.11
期望：这个函数返回去重后的列表，保持原顺序
实际：返回的列表顺序乱了
代码：
def dedup(items):
    return list(set(items))

报错/现象：dedup([3,1,2,1]) 返回 [1,2,3]，我要 [3,1,2]

请先分析原因，再给最小修改，不要改其他部分。
```

**AI 的结果：** 立刻指出 `set()` 无序，给出 `dict.fromkeys()` 方案，一改就对。

## 案例 2：写文档

### ❌ 坏的

```
写个 README
```

**AI 的结果：** 生成一份通用的模板，跟你的项目毫无关系。

### ✅ 好的

```
给我的项目写 README。
项目：机器人远程监控面板
技术栈：FastAPI + WebSocket + Vue3
核心功能：多设备接入、实时数据流、告警推送
部署：Docker Compose
受众：想快速上手的开发者

要求：
- 第一段一句话说清这是什么
- 默认读者不懂这个领域，术语要解释
- 要一个"5 分钟跑起来"的章节
- 用 mermaid 画架构图
- 不要营销话术
```

**AI 的结果：** 一份能直接用的 README。

## 案例 3：学习理解

### ❌ 坏的

```
讲一下 Kubernetes
```

**AI 的结果：** 3000 字的百科式介绍，读完还是不会用。

### ✅ 好的

```
我想理解 Kubernetes 是干什么的。
我是后端开发者，会 Docker，但没接触过 K8s。

请用反问式教学：
- 一次只问我 1-2 个问题
- 根据我的回答决定往下讲什么
- 用类比，别堆术语
- 最后给我 3 条核心结论 + 1 个可以动手的下一步
```

**AI 的结果：** 一路问、一路答，最后你真的懂了。

## 案例 4：做决策

### ❌ 坏的

```
用 PostgreSQL 还是 MySQL？
```

**AI 的结果：** 列出两边各 10 条优缺点，你还是不知道怎么选。

### ✅ 好的

```
帮我决定数据库选型。
场景：物联网设备数据，每天写入 500 万条，
      查询以时间范围为主，团队 3 人，都用过 MySQL。

要求：
1. 先问我不超过 2 个关键问题
2. 给我一个明确推荐，并说清最可能错在哪
3. 说清如果选错了，迁移成本有多大
```

**AI 的结果：** 给出明确推荐 + 迁移路径，你能拍板。

## 案例 5：反向思考（红队）

### ❌ 坏的

```
这个方案好吗？
```

**AI 的结果：** "挺好的！"——毫无价值。

### ✅ 好的

```
请扮演反对者，攻击下面这个方案。
按严重程度排序：问题 → 为什么严重 → 建议怎么改。
不要给优点，只要问题。

方案：
[粘贴你的方案]
```

**AI 的结果：** 挖出你自己没想到的漏洞。

---

## 总结：好提问的公式

```
背景（我是谁/在做什么）
  + 目标（要什么产物）
  + 现状（已有的材料/报错）
  + 约束（技术栈/长度/风格/禁止项）
  + 验收（怎么算完成）
```

**外加两个杀手锏：**
- 复杂任务先让它**复述确认**
- 要批判意见就明确说**"只要问题，不要优点"**
